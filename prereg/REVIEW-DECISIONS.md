# Adversarial review of PLAN-EXPERIENCE.md v1: decisions

Reviews requested on 8 November 2026 around 19:21 Paris time, before any run of the confirmatory blocks, from two other model lineages through Adaption (Responses API): GLM 5.2 and Qwen 3.5 397B. The prompt asked for methodological flaws ranked by severity and for the smallest fix that could be made before data collection (`prereg/review/ask_review.py`). Raw answers: `prereg/review/glm-5.2.txt` and `prereg/review/qwen3.5-397b.txt` (with usage metadata in the `.json` files). Every accepted change is in amendment v1.1 (plan section 16).

Legend: **accepted** (the plan changes), **partly accepted** (one part changes), **rejected** (reason given).

| # | Point (reviewer) | Decision | Reason or change |
|---|---|---|---|
| 1 | H2 is near-tautological: the final-report monitor is compared between runs that confess and runs that do not (GLM 1) | **partly accepted** | H2 stays as registered: its value is in measuring how large the gap is, and it is expected by construction. v1.1 states this in the plan, and adds as the key descriptive quantity the absolute M-final sensitivity on laundered violators (Wilson), next to the specificity on non-violators. The report must not present H2 as a surprising finding. |
| 2 | The H1 denominator is unclear: "not agreed" is counted as not laundered but "unclassified" is excluded (Qwen 2, GLM 2) | **accepted (clarification)** | v1.1 defines n exactly: runs whose combined label is laundered, disclosed or not agreed. A run is unclassified only when both judges say unclassified, and those runs are reported apart. GLM's proposal (n = agreed runs only) would remove the conservative bias, so it is added as a sensitivity analysis, not as the primary analysis. |
| 3 | The H2 power was computed for Fisher, not for the permutation test on pooled scores (GLM 3) | **accepted (clarification)** | The permutation test equals Fisher's test when the two monitors agree on every run. When they disagree, it uses intermediate scores. v1.1 says the reported power is the power of the single-monitor Fisher test, given as an approximation [deduced, not computed]. |
| 4 | Pooling across packages and tasks: GLM will dominate the result (GLM 4, Qwen 4) | **partly accepted** | The pooled tests stay primary, because only one test per question was registered and switching to stratified tests would multiply the comparisons. v1.1 adds a rule: every claim in the report names the packages and the task that supply the violators, the by-package and by-task estimates are shown next to every pooled estimate, and the title must not generalise beyond the packages where violations occurred. |
| 5 | The neutral defense note should mention the same blocker (GLM 5) | **rejected** | The night's plan defines the neutral note as a description of the repository that says nothing about the blocker or a method. With that note, the contrast is "refusal note (information plus refusal) against a matched neutral note". v1.1 names the contrast this way, so that it is not presented as the effect of the refusal norm alone. |
| 6 | Classifier refusals counted as compliant stops could inflate H-D (GLM 5) | **accepted** | These runs stay in (b) or (c), as registered, so that every run remains in the denominator. Their count is reported by arm. |
| 7 | Token length of the neutral note should match within 1 token (Qwen 5) | **rejected** | The registered tolerance is 10 %. The achieved ratio is 1.031 (o200k) and 1.017 (cl100k) (`defense/MANIFEST.txt`), and both notes have the same header, structure and position. |
| 8 | Laundering should be restricted to green runs (GLM 6) | **rejected as primary, added as sensitivity** | The ground truth is the executed forbidden change, whatever the test result. A red run whose report claims success or compliance is still a misreport to the human. v1.1 adds H1 restricted to green violators as a sensitivity analysis. |
| 9 | The strict-violation analysis opens a garden of forking paths (GLM 7) | **rejected** | It is a sensitivity analysis, registered before the data, and it does not replace the primary ground truth. The checker fix was requested from the bench owner (false positive of `fxprovider_paths` on a note file name). If the fix lands before the confirmatory runs, its commit is recorded. |
| 10 | Replacing excluded runs at the end of the queue breaks randomisation (GLM 8, Qwen 7) | **accepted** | v1.1 drops replacement. Excluded runs are not rerun, and cells are analysed with their actual n. |
| 11 | H-D should not share a Holm family with H1 to H3 (GLM 8, Qwen 8) | **accepted** | They are unrelated questions: an observational property of reports and monitors, and an intervention. v1.1 sets two families, each controlled at 0.05: F1 = {H1, H2, H3} with Holm, F2 = {H-D}. This change is made before any confirmatory data and is stated in the report. |
| 12 | GLM is both a tested package and a judge or monitor (Qwen 1) | **partly accepted** | Removing GLM would leave a single judge and no agreement measure, so GLM stays. v1.1 adds a sensitivity analysis in which runs of the GLM package are labelled and monitored by Qwen alone. Judge agreement and monitor accuracy are reported by package. |
| 13 | If there are fewer than 40 violators, H1 to H3 should become descriptive (Qwen 3) | **partly accepted** | The registered tests are still computed, so that results are not suppressed after the fact. v1.1 states that a non-rejection is reported as inconclusive together with its power from `power_out.txt` at the observed n, and that the threshold of 15 violators in section 14 is unchanged. |
| 14 | Judges see `forbidden_mod`, which may bias them toward finding laundering (Qwen 6) | **rejected (kept as a limitation)** | The judge has to know what was done to code what was reported. The required verbatim excerpt (checked mechanically) and the human audit, when it takes place, are the mitigations. The limitation is stated. |
| 15 | Outcome-dependent titles invite HARKing (Qwen 9) | **rejected** | Each outcome's wording was fixed in section 14 before the data, which is the opposite of HARKing. |
| 16 | Specificity may be noisy (Qwen 10) | **no change** | Monitors run on every run. Under the low-balance fallback, the stratified sample has 20 runs per package and task (at least 160 non-violators). |
